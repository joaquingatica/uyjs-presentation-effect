## ¿Cómo mejorar esto?

Usando el concepto de un **efecto** que **declare** lo que va a suceder.

<v-click>

Representado como:

```ts
//            ┌─── Tipo del resultado
//            │        ┌─── Tipo del error
//            │        │      ┌─── Las dependencias
//            ▼        ▼      ▼
type Effect<Success, Error, Requirements>
```

</v-click>

<v-clicks>

- Es el tipo base del framework
- Cada effect es una unidad de cómputo autónoma
- Una variable de tipo `Effect` describe y contiene lo que se va a ejecutar
- El framework provee APIs y librerías para componer Effects

</v-clicks>

## Creando Effects

Declarando un comportamiento sin ejecutarlo aún.

```ts
type Effect<Success, Error, Requirements>
```

<br />

::left::

```ts {1,2|4-5|7-11|13-17}
// Effect<User, never, never>
const program = Effect.succeed(new User({ id: 1, name: 'John' })

// Effect<never, ParseError, never>
const program = Effect.fail(new ParseError('Invalid'))

// Effect<User, ParseError | HttpError, HttpClient>
const program = Effect.gen(function* () {
  const data = yield* fetchUsers
  return yield* parseUserFromData(data)
})

// Effect<User[], DbError, DbService>
const program = Effect.gen(function* () {
  const { getUsers } = yield* DbService
  return yield* getUsers()
})
```

::right::

<v-click>

Utiliza generators para **componer y establecer
dependencias** entre effects.

`yield*` "pide" resultado de otro `Effect`.

Similar al `await` de una `Promise`.

</v-click>

## Ejecutando Effects

Un `Effect` describe, el framework lo ejecuta. ¿Cómo?

<v-click>

Agnóstico a la plataforma:

```ts {3-4|6-7}
const program = Effect.succeed(1)

// result: number
const result = Effect.runSync(program)

// result: Promise<number>
const result = Effect.runPromise(program)
```

</v-click>

<v-click>

Específico a la plataforma:

```ts {1|5}
import { NodeRuntime } from '@effect/platform-node'

const program = Effect.succeed(1)

NodeRuntime.runMain(program)
```

</v-click>

## Desmitificando el `pipe`

¿Qué es `pipe`? Una forma de **componer funciones** de manera legible.

<br />

::left::

<v-click>

**JavaScript tradicional:**

<!-- prettier-ignore-start -->
```ts
// Encadenamiento de métodos + variables intermedias
const yearString = 'mvd js 2025 '
  .trim()
  .slice(-4)

const year = Number.parseInt(yearString, 10)

// year: 2025
```
<!-- prettier-ignore-end -->

Funciona cuando los métodos están en el prototipo.

</v-click>

::right::

<v-click>

**Con pipe:**

<!-- prettier-ignore-start -->
```ts
// Composición de funciones
const year = pipe(
  'mvd js 2025 ',
  trim,
  slice(-4),
  parseInt(10)
)
// year: 2025
```
<!-- prettier-ignore-end -->

Funciona con **cualquier función**, no solo métodos.

</v-click>

## ¿Cómo funciona `pipe` conceptualmente?

<v-clicks>

```ts
// Con 1 función
const pipe = (x, fn1) => fn1(x)

// Con 2 funciones
const pipe = (x, fn1, fn2) => fn2(fn1(x))

// Con 3 funciones
const pipe = (x, fn1, fn2, fn3) => fn3(fn2(fn1(x)))

// Con N funciones
const pipe = (x, ...fns) => fns.reduce((acc, fn) => fn(acc), x)
```

</v-clicks>

<v-clicks>

El dato fluye de **izquierda a derecha**, transformándose en cada paso.

Las funciones del pipe tienen que tener **firmas compatibles**.

</v-clicks>

## `pipe`: El Builder Pattern de Effect

En Effect, `pipe` es la forma de **componer y transformar** efectos.

<v-clicks>

```ts
// Como un builder pattern funcional
const program = pipe(
  getUser(userId), // obtener usuario
  Effect.andThen(sendEmail), // enviar email
  Effect.retry({ times: 3 }) // reintentar si falla
)
```

**Ventajas:**

- ✅ Menos carga cognitiva (no hay que nombrar intermedios)
- ✅ Fácil inyectar y modificar comportamiento
- ✅ Funciones puras y componibles
- ✅ Builder pattern funcional

</v-clicks>
