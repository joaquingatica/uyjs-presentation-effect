# Introduciendo efectos

<br />

<v-click>

#### **Un _Effect_ es una estructura que describe un programa, sin ejecutarlo aún.**

Declara el resultado, errores posibles y dependencias:

```ts
//            ┌─── Tipo del resultado
//            │        ┌─── Tipo del error
//            │        │      ┌─── Las dependencias
//            ▼        ▼      ▼
type Effect<Success, Error, Requirements>
```

</v-click>

<v-click>

Que se puede entender como:

<!-- prettier-ignore-start -->
```ts
type LazySafePromise = (context: Requirements) => () => Promise<Result<Success, Error>>
```
<!-- prettier-ignore-end -->

<sub>
* Disclaimer: es una sobre-simplificación, pero ilustrativa
</sub>

</v-click>

## Creando Effects

Declarando un comportamiento sin ejecutarlo aún.

```ts
type Effect<Success, Error, Requirements>
```

<br />

::left::

```ts {1,2|4-5|8,11,14,15|7-15}
// Effect<string, never, never>
const program1 = Effect.succeed('Hello World!')

// Effect<never, ParseError, never>
const program2 = Effect.fail(new ParseError('Invalid'))

// Effect<User, ParseError | HttpError, HttpClient>
const program3 = Effect.gen(function* () {
  //     ┌─ unknown    ┌─ Effect<unknown, HttpError, HttpClient>
  //     ▼             ▼
  const data = yield* fetchUsers
  //              ┌─ (unknown) => Effect<User, ParseError, never>
  //              ▼
  return yield* parseUserFromData(data)
})
```

::right::

<v-click>

Utiliza generators para **componer y establecer
dependencias** entre effects.

`yield*` "pide" el resultado o "tira" el error de otro `Effect`.

Similar al `await` de una `Promise`.

</v-click>

## Ejecutando Effects

Un `Effect` describe, el framework lo ejecuta. ¿Cómo?

<v-click>

Opción 1) Agnóstico a la plataforma:

```ts {hide|3-4}
const program = Effect.succeed(1)

// result: Promise<number>
const result = Effect.runPromise(program)
```

</v-click>

<v-click>

Opción 2) Específico a una plataforma:

```ts {hide|1,5}
import { NodeRuntime } from '@effect/platform-node'

const program = Effect.succeed(1)

NodeRuntime.runMain(program)
```

</v-click>

## Desmitificando el `pipe`

Es una forma de **componer funciones** de manera más legible.

::left::

<v-click>

**JS tradicional:**

<!-- prettier-ignore-start -->
```ts
// Encadenamiento de métodos + variables intermedias
const yearString = 'mvd js 2025 '
  .trim()
  .slice(-4)

const year = Number.parseInt(yearString, 10)
// year: 2025
```
<!-- prettier-ignore-end -->

Funciona con métodos del `prototype`.

</v-click>

::right::

<v-click>

**Utilizando pipe:**

<!-- prettier-ignore-start -->
```ts
// Composición de funciones
import { pipe, String, Number, Option } from 'effect'

const year = pipe(
  'mvd js 2025 ',
  String.trim,
  String.slice(-4),
  Number.parse,
  Option.getOrNull
)
// year: 2025
```
<!-- prettier-ignore-end -->

Funciona con **cualquier función**, no solo métodos.

Las funciones **transforman** el dato "mientras fluye".

</v-click>

## Analicemos

Veamos en detalle un código casi production-ready:

```ts {hide|all|3,4|5,16|5,6,16|5,7-9,16|5,10-12,16|3,5,10-12,16|5,13,16|5,14,16|5,15,16|all}
import { Effect, pipe } from 'effect'

// Effect<void, UserError, DbService | SmsService>
const sendSmsToUser = (userId: UserId) =>
  pipe(
    userId,
    //     ┌─ (UserId) => Effect<User, UserError, DbService>
    //     ▼
    getUserById,
    //               ┌─ (User) => Effect<void, SmsError, SmsService>
    //               ▼
    Effect.andThen(sendSms),
    // ◀─ Effect<void, SmsError | UserError, SmsService>
    Effect.retry({ times: 3 }),
    Effect.tap(Effect.log('User notified successfully!')),
    // NOTA: manejamos el `SmsError` localmente y propagamos los demás errores
    Effect.catchTag('SmsError', () => Effect.void)
  )
```
