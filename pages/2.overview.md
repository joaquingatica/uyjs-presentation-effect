## ¿Cómo mejorar esto?

Usando el concepto de **Efecto** que **declare** lo que va a suceder.

<v-click>

Representado como:

```ts
//            ┌─── Representa el tipo del resultado
//            │        ┌─── Representa el tipo del error
//            │        │      ┌─── Representa dependencias
//            ▼        ▼      ▼
type Effect<Success, Error, Requirements>
```

</v-click>

<v-clicks>

- Es el tipo base del framework
- Cada effect es una unidad de cómputo autónoma
- Una variable de tipo `Effect` describe y contiene lo que se va a ejecutar
- El framework provee APIs y librerías para componer Effects

</v-clicks>

## Creando Effects

Declarando un comportamiento sin ejecutarlo aún.

```ts
type Effect<Success, Error, Requirements>
```

<br />

::left::

```ts
// Effect<User, never, never>
const program = Effect.succeed({ id: 1, name: 'John' })

// Effect<never, ParseError, never>
const program = Effect.fail(new ParseError('Invalid'))

// Effect<User, ParseError | HttpError, never>
const program = Effect.gen(function* () {
  const data = yield* fetchData
  return yield* parseUserFromData(data)
})

// Effect<User[], DbError, DbService>
const program = Effect.gen(function* () {
  const { getUsers } = yield* DbService
  return yield* getUsers()
})
```

::right::

Utiliza generators para **componer y establecer
dependencias** entre effects.

- `yield*` "pide" resultado de un `Effect`
- `function*` declara un `Effect`

Similar al `await` de una `Promise`

---
layout: default
---

## Ejecutando Effects

```ts
const program = Effect.succeed(1)

// result: number
const result = Effect.runSync(program)

// result: Promise<number>
const result = Effect.runPromise(program)

// result: RuntimeFiber<number, never>
const result = Effect.runFork(program)
```
